# CleanSight

CleanSight is a web application for monitoring trash bins from images. It lets users upload a photo, get an initial classification ("full" or "empty"), correct that annotation, and view the collected data in a dashboard.

## Features

- Account creation and login for `@paris.fr` addresses, with an agent code in the format `AGP-1234`.
- Image upload, preview, classification suggestion and manual validation/correction.
- Image history, annotations, statistics and recommendations.
- Dashboard with indicators, charts and location data.
- Viewing and editing of the classification rules.
- Password reset by email, if the email sending service is configured.

## Architecture

- **Frontend:** Vue 3, Vite, Vue Router, Pinia, Tailwind CSS, Chart.js and Leaflet.
- **Backend:** Flask REST API, SQLAlchemy, JWT authentication, Pillow, NumPy and OpenCV.
- **Database:** PostgreSQL is used by the provided configuration.

## Prerequisites

- Python 3.10 or later.
- Node.js compatible with Vite 7: 20.19+ or 22.12+.
- PostgreSQL accessible from the backend.

## Running locally

### 1. Set up PostgreSQL and the backend

Create a PostgreSQL database (for example `cleansight`), then install the Python dependencies:

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Configure the environment variables in this terminal. `DATABASE_URL` must point to your database; the two secret keys must be unique and must not be published:

```bash
export DATABASE_URL="postgresql://UTILISATEUR:MOT_DE_PASSE@localhost:5432/cleansight"
export SECRET_KEY="remplacer-par-une-cle-secrete-aleatoire"
export JWT_SECRET_KEY="remplacer-par-une-autre-cle-secrete-aleatoire"
```

`DATABASE_URL` is the variable name read by the application (not `DB_URL`). With these variables set, create the tables then start the API:

```bash
python create_tables.py
python run.py
```

The API is then available at `http://127.0.0.1:5000`. `run.py` starts Flask in debug mode: this command is intended for local development only.

To send welcome and password reset emails, also configure `MAIL_USERNAME` and `MAIL_PASSWORD` for your SendGrid SMTP relay. Without these credentials, the features that send emails are not guaranteed to work.

### 2. Start the frontend

In another terminal:

```bash
cd frontend
npm install
```

Create `frontend/.env.local` with the API base URL, without a trailing slash:

```dotenv
VITE_API_URL=http://127.0.0.1:5000
```

Then start Vite:

```bash
npm run dev
```

Then open the address displayed by Vite (usually `http://localhost:5173`). The local origins `localhost:5173` and `127.0.0.1:5173` are allowed by the backend's CORS configuration.

## Main API

| Method | Route | Description |
|---|---|---|
| `POST` | `/auth/signup`, `/auth/login` | Account creation and login |
| `POST` | `/auth/logout`, `/auth/refresh` | Logout and token renewal |
| `GET` | `/auth/me` | Profile of the logged-in user |
| `GET` | `/auth/reset-password/<token>` | Reset link verification |
| `POST` | `/auth/forgot-password`, `/auth/reset-password` | Password reset |
| `POST` | `/predict` | Analyze an image without saving it |
| `POST` | `/validate` | Save an annotated image |
| `POST` | `/upload` | Authenticated upload with annotation |
| `GET` | `/images` | List of images, with annotation and date filters |
| `PATCH`, `DELETE` | `/images/<id>` | Edit the annotation or delete |
| `GET` | `/dashboard/*` | Statistics, recent images, map and recommendations |
| `GET`, `PUT` | `/rules` | Read and update the rules |

Uploaded images are stored in `backend/uploads/`.

## Classification and metadata

The backend extracts, among other things, the dimensions, file size, average colors, contrast and number of contours, then applies JSON rules. The editable rules are located in `backend/utils/rules.json`.

Metadata generation queries external geocoding and weather services. **The coordinates generated by the current code are random within Paris; they do not come from the actual location of the photo.** The map should therefore not be considered a verified location of the trash bins.

## Tests and production

- The frontend provides `npm run build` to check and compile the application.
- No frontend test script is declared. The Python tests present are partial and some expect sample images that are not provided in the repository; they do not yet constitute a complete, runnable test suite.
- `Dockerfile`, `docker-compose.yml` and `run.sh` at the root are empty: no Docker procedure or launch via this script is currently available.
- The `run.py` configuration is intended for development. A production deployment requires, among other things, a WSGI server, dedicated secrets and a secure configuration of cookies and HTTPS.
